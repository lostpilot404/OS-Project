# Drift & Uncertainty Evaluation — phase_transition drift, estimator=True cv=0.3

**Workloads:** 7 traces (1 reps × 7 families: short_jobs, long_jobs, mixed, cpu_bursty, priority_skewed, staggered_interactive, poisson_arrivals), seed 23819, drift `phase_transition` via workload/drift.py at fraction 0.35 (deterministic per-workload seed, pre-injection prefix identical).
**Workload families:** 7 synthetic families (arrival pattern × burst distribution × priority). Training uses 6 families cycling (all but poisson_arrivals, which is held out to test distribution shift); testing uses all 7. Each trace has 15 processes by default; burst_shock multiplies post-injection bursts by 4.0, arrival_storm compresses post-injection gaps by 0.35, etc. See config.py and workload/drift.py for exact generators.
**Estimator:** enabled; when enabled EWMA per-bucket over completed totals (observable service sums, alpha=0.5), log-normal multiplicative noise `exp(N(bias, sigma²))` where `sigma = error_cv = 0.3` is the log-space standard deviation (parameter name `burst_estimator_error_cv` retained for backward compatibility; not mathematically identical to the multiplier's CV `sqrt(exp(sigma²)-1)` ≈ 0.307 for sigma=0.30) bias=0.0 via derive_seed; observable source = dispatched service history (no hidden burst/remaining used); ground truth retained only for evaluation via EstimationError (not used for decisions). When enabled=False, controller sees exact remaining_burst (simulator assumption, same as frozen study). SJF baseline `fixed_sjf` always uses exact burst_time (oracle, not equal-information) even when estimator is enabled for adaptive arms; no estimated-burst SJF variant is included in this run. Sampling behavior unchanged (parameter name and value retained).
**Training:** 5 Q tables, 2 episodes/seed on stationary workloads (6 families, poisson_arrivals held out); test on drifted workloads never seen in training. Seeds: [7101, 7102, 7103, 7104, 7105].
**Evaluation:** Each workload instance presented to every arm (paired by fingerprint); 7 traces for single-policy arms, 35 for q_recovery (5 seeds). Metrics via evaluation/reliability.py and evaluation/metrics.py. Bootstrap: family-stratified crossed bootstrap 1000 replicates seed 104729, same as frozen study.

**Formulas & denominators (explicit):**
- mean_waiting = sum(waiting_time)/n, waiting_time = completion−arrival−burst per process (includes preemptions); per-trace p95 = ceil(0.95n)th ordered waiting — with n=15 per trace, ceil(0.95*15)=15 so per-trace p95 is definitionally the max (not evidence about tail shape); max = max(waiting); pooled_p95_waiting = ceil(0.95*N)th over all process waits pooled across traces (N≈1050 for 70-trace arms, 5250 for q_recovery), interpretable tail; starved = count(waiting > 3×median); fairness = (sum w)²/(n sum w²) (Jain, 1=perfect); throughput = n/total_time; cpu_util = 100×busy/total_time; switches = count(pid changes); switching_overhead = switches×switching_cost.
- incidents = detector events; interventions = action_changed (HOLD excluded); rollback_rate = (rejected+inconclusive)/interventions (per trace, mean over traces); recovery_delay_decisions = mean verification_decisions per incident (where incidents>0); fallback = any incident with fallback_triggered (safe fallback after 2 consecutive confirmed failures).
- false_intervention_rate = share of interventions with matched_gain≤0 from counterfactual audit (requires audit; None in lightweight drift script — see frozen study's healing_audit.csv for full audit). regression_rate = share of traces where mean_waiting > baseline trace at same (family,rep) (for q_recovery: mean over 5 seeds per workload vs baseline).
- Aggregation: per-arm means over traces (for q_recovery over all seed/workload records, not independent workload counts); comparisons are paired per-workload differences, family-stratified.
