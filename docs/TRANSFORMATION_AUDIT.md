## 4. Defects found and fixed during the transformation

| Defect | Effect | Fix |
|---|---|---|
| `MappedRulePolicy.select` ignored the masked action set | rule arms requested quantum changes under non-Round-Robin policies, which collapsed to no-ops and inflated "intervention" counts (54 such requests in an early smoke run) | the rule now honours the mask, falls back to its declared alternative, then to `hold`, and records which it used |
| The work gate compared `visible_remaining_work` (CPU time) with `min_remaining_work_factor × reference_wait` (waiting time) | mixed units blocked almost every intervention | the gate now compares visible work with the trace's observed mean burst, and the detector takes `observed_mean_burst` explicitly |
| The verification rule used absolute improvement over the trace's normal level | *94.6 %* of no-action windows on the training control "improved" (a trigger is a local maximum, and the statistic decays by itself), so the rule certified noise | replaced by the normalised load closure, with `accept_closure_factor` derived from the control's 95th percentile; measured false-accept rate falls to 4.5 % (training) / 3.1 % (validation) |
| The single-threshold closure verdict called every non-accepted window a failure | because the closure statistic of a trigger is a local maximum that decays anyway, the rule treated helpful interventions as failures, rolled them back and charged them a rollback penalty — the *verification mismatch* this round investigated | replaced by the phase-adjusted residual of the same statistic with **two** boundaries (95th/5th percentile of the control residual, +0.30/−0.30) and a third **`inconclusive`** verdict: it rolls back like a failure but is not one, carries no rollback penalty and cannot trigger the fallback. `post_load_baseline` (the phase model: no-action post-load from the trigger's queue level, ready-set size and visible work; 96.1 % of the post-load variance, 80.2 % of the null closure's spread) is declared in the config and derived from the training control, and the specification comparison is written to `healing_verification_models.csv`. Measured effect in the frozen run (`23819`): **65 of 65 accepted interventions were genuinely helpful** (base rate 83.9 %), 76.5 % of rejected ones were harmful (5.5× the 14.0 % base rate), and the certification ceiling (6.7 % of helpful interventions) is reported instead of hidden |
| The per-arm audit summary pooled two counterfactuals | one row per intervention and one row per episode ("never heal again") shared a denominator, so `audited_interventions`, the false-recovery rate and the accept/reject shares were computed on a mixture: `n` for `rule_wait` read 280 instead of 144 | the aggregate and the generated report now separate the two populations explicitly (`intervention` rows vs `episode_level` rows, each with its own table), and a test pins that every rate in the aggregate has an intervention denominator |
| A window still open when the trace ended was logged as `censored` with NaN evidence | the ledger mixed verdicts and censored rows, and the posture for a truncated window was undefined | `end_episode` now concludes the window as `inconclusive` with the reason `insufficient_evidence_window_truncated` and applies the declared posture (rollback to the last accepted configuration); the test suite asserts the rollback target and the final configuration for that case |
| The reward charged a fixed cost for every detected event and the closure statistic did not exist | exploding/high-magnitude rewards in early development | the reward is now the same closure statistic minus the declared cost (1 % per change, 2 % on rollback), so holding and acting are on one scale |
| Demo artifact could mix controllers | the demonstration re-run used the first arm with the matching name, not the training seed of the selected episode, and the incident table was not filtered by seed | the payload now selects `(arm name, training seed)` and refuses to write if the replay does not reproduce the recorded incident count |
| No-op actions were charged and logged as recoveries | false "interventions" in the ledger | an action that cannot change the live configuration reports `changed=False`; it is logged as `held`, never as a recovery |

Checks that were made explicitly, not assumed:

* the detection-only control reproduces FCFS to the last digit (schedule, switches, metrics);
* rollback is applied at the first epoch at or after the verification window's end; after the
  safe fallback a trace uses exactly one pinned configuration;
* a counterfactual replay reproduces the recorded decision prefix exactly, and re-applying the
  recorded action at an incident reproduces the run up to and including that epoch;
* rebuilding a split returns byte-identical workloads, and the three splits share no
  fingerprint;
* two runs of the same frozen configuration produce identical metrics, comparisons, audit
  summaries and demonstration traces — after the last source change this was extended to the
  whole artifact set: all 20 files under `results/healing/` and all 3 figures were byte-identical
  (md5) between the canonical run and an independent run into `/tmp/det-probe`;
* `results/healing/healing_*` read back from disk and equal the in-memory frames the report was
  rendered from;
* `git diff --check` is clean; no `.venv`, cache, log or secret is staged.

## 6. What remains unfixed (reported, not hidden)

* The loop does not beat fixed SJF. This is a measured result, described in
  `docs/EVALUATION_RESULTS.md` and `docs/LIMITATIONS.md`.
* The verifier filters the tails but cannot certify the ordinary case: at the declared 5 %
  false-accept budget only 6.7 % of the genuinely helpful interventions clear the boundary, and
  91.0–92.1 % of them end `inconclusive` and are rolled back after the window. The measured
  reason (the best action moves the statistic by 0.95 of the residual spread one window shows,
  ≈ 39 windows would be needed for 80 % power) is documented; closing that gap is *not*
  implemented.
* Residual detector false triggers (0.66 events per trace on the held-out control, 0.70 per
  stable trace in the injection probe) against a 75.0 %/56.4 % recall on the two injected
  degradations.
* Sparse Q coverage: 3.8–7.2 % of the *reachable* state-action pairs and 1.1–1.3 % of the
  declared table (29–33 of 648 states), flat after ~900 training episodes.
* No real-OS integration, by design.
